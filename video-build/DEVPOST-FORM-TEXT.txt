PROJECT TITLE

Custodian — the authority kernel for AI agents

================================================================
TAGLINE / ONE-LINE DESCRIPTION

An open-source policy kernel that decides whether an AI agent's

================================================================
PROJECT DESCRIPTION (long form)
================================================================
Custodian is an open-source safety kernel for AI agents. The
kernel sits between any agent and its tools: it classifies every
proposed action, denies the destructive ones, escalates the
ambiguous ones, and writes a tamper-evident HMAC receipt for
every decision. The kernel is agent-agnostic and works with any
tool-calling agent (Codex, Claude, Gemini, and others). Prompts
are soft. A smart enough model routes around soft instructions.
Custodian moves the decision outside the agent's process — into a
kernel the agent cannot modify, cannot inspect, and cannot
self-approve through.

## What ships

- The kernel: typed action model, policy engine, fail-closed
  gate, value-free HMAC-chained receipt ledger with chain
  verification and tamper detection.
- The credential broker: secrets materialize at egress, never in
  the agent, never in the prompt.
- The MCP server: humans stay in the loop through a standard MCP
  boundary for any escalation.
- The Codex Guard adapter (Build Week contribution): the policy
  bridge for OpenAI's Codex CLI, a `custodian codex-guard`
  subcommand suite, and the full Codex threat-model test coverage.

## What we built during OpenAI Build Week

We added the Codex Guard adapter to the existing Custodian
kernel. Codex + GPT-5.6 implemented:

- The policy bridge between Codex's tool-call format and the
  kernel's typed action model.
- The `custodian codex-guard receipts` subcommand with
  pretty-printed ledger output, `--verify` chain check,
  `--limit N`, and graceful handling of malformed lines.
- The single-use human-approval protocol with digest-bound grants
  (the human's approval is bound to the exact action it
  approves — replay fails).
- The MCP server integration for the in-protocol escalation
  channel.
- 110 tests across 7 files: kernel, policy wiring, self-approval
  regression, gate fail-closed, classifier adversarial cases,
  receipts CLI, end-to-end demo.

GPT-5.6 powered the contextual risk analysis. Every proposal gets
a written reason. The deterministic rules keep final control
over what is prohibited. GPT-5.6 explains; the rules decide.

Codex also attacked its own classifier: it generated adversarial
cases (actions whose declared type understates their actual risk —
reads that traverse symlinks, writes to sensitive paths, grant
requests that look autonomous but aren't) and confirmed the kernel
caught them, then shipped the regression tests so future
classifier regressions get caught at the gate.

## What the receipt ledger proves

Every decision writes a value-free receipt: action type, tool,
verdict, reason, timestamp, HMAC of the prior receipt. The chain
is HMAC-bound — modifying any historical receipt breaks the
chain at that point, and the verifier flags it. Receipts contain
no secret material, so they can be audited, shared, or shipped
to a regulator without redaction.

A live demo: `custodian codex-guard receipts --verify` reads the
ledger, walks the chain, and prints
`chain OK (105 decisions, HMAC-verified)` or
`chain BROKEN at offset 47 — receipt hash mismatch`.

## Why the kernel, not a prompt

Prompts are soft. A model that reasons itself into approving its
own refund will approve its own refund. Custodian moves the
decision outside the model's process and outside the model's
code path. The agent proposes. The kernel decides. The ledger
proves. The kill switch stops.

"WHAT PROBLEM DOES YOUR PROJECT SOLVE?"
================================================================
AI agents are already moving money, deploying infrastructure,
and reading credentials. Today the only thing standing between
a tool call and a production system is the model's own
prompt — which is soft, and a sufficiently smart model will route
around it. The result is a slow-motion data breach waiting on a
prompt-injection attack or a reasoning failure.

Custodian moves the safety boundary out of the model. The agent
proposes an action. The kernel, running outside the agent's
process, classifies it. Destructive actions deny. Ambiguous
actions escalate through a human. Safe actions pass. Every
decision — allow, deny, escalate — gets a tamper-evident HMAC
receipt. Auditors can verify the chain. Operators can replay
exactly what the agent did. Investigators can prove nothing
was tampered with after the fact.

Codex ran the build. It implemented the policy bridge, the

Codex also attacked the classifier. It generated adversarial

risk (reads that traverse symlinks, writes to sensitive paths,

the kernel catches them, and shipped the regression tests.
The demo in the video is one of those cases.

GPT-5.6 powered the contextual risk analysis. Every proposal
gets a written reason. The deterministic rules (path fence,
secret-leak guard, prompt-injection guard, kernel self-protection)
keep final control over what is prohibited. GPT-5.6 explains;
the rules decide.

The architectural decision we made: enforcement lives outside
the acting agent. The model never approves its own exception.
The receipts it never sees are the receipts you can trust.
