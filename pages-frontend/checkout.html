What the kernel does with your payment

1

Payment received — VERIFIED earn

Your Stripe PaymentIntent hits our webhook. The kernel logs it as a VERIFIED earn event. The claim verifier checks the ledger: $25 inbound matches the Stripe object. No fabrication possible.

VERIFIED — ledger matches
2

Kernel gates the review cost

Running verify_kit costs compute. The kernel evaluates the spend request — band L2, within cap. AUTONOMOUS. No human needed. The review starts immediately.

AUTONOMOUS — within band L2
3

If you request a refund — ESCALATED

Refunds involve self-dealing: the agent cannot approve its own outgoing payment. The kernel catches this, escalates to a human operator, and nothing moves until we approve it. The agent cannot bypass this.

ESCALATED — self-dealing detected
4

SHA-256 receipt for every action

Each step produces a GovernedReceipt — fingerprinted with SHA-256 over receipt_id:band:amount:verdict:output_hash. Tamper any field, verify() fails. Every action is auditable, forever.

Questions

Is this a real Stripe charge?
Yes. Your payment goes through Stripe's real infrastructure. You get a real PaymentIntent ID that you can verify on stripe.com. The kernel logs the earn event and produces a SHA-256 receipt. Refunds are available — the kernel escalates refund requests to a human operator (by design).
What do I get in the safety report?
A written analysis of your AI agent workflow: which authority bands your tools should be in (L0–L4), whether self-approval loops exist, where a kill switch should be placed, and what your policy.yaml should look like. Delivered within 48h via email.
Why does a refund require human approval?
Because the agent cannot approve its own outgoing payments — that's self-dealing. The Custodian kernel detects this pattern, sets verdict to ESCALATED, and blocks execution until a human operator approves it. This is the same control that caught the self-approval attack in the demo.
Can I verify the kernel code myself?
Yes. pip install custodian-kernel then python3 -m pytest tests/ --tb=no -q. All 1,298 tests are public. The claim verifier, authority bands, kill switch, and receipt system are all in the package.
