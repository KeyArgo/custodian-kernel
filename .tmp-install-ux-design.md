# Install UX design request — custodian 0.5.0

Read this file. Do NOT edit anything. Return a concrete UX design.

## The product
Custodian is a governance kernel for AI agents. Components:
- core kernel + Paladin credential broker (MANDATORY — Paladin always installs)
- Claude Code guard (optional)
- Codex guard (optional)
- Hermes guard (optional; also distributed as a Hermes plugin)
- stripe/talaria integrations (optional, separate)

## Current state (just committed, one-install-everything fold)
- One wheel `custodian-kernel` 0.5.0 contains ALL modules (kernel + paladin + 3 guards) + all console scripts (custodian, paladin, custodian-codex, custodian-claude, custodian-hermes, ...) + a Hermes plugin entry point (hermes_agent.plugins → custodian.hermes_guard.plugin).
- Install routes: `pip install custodian-kernel` | `python install-custodian.py` (PEP 668 managed installer) | git clone + install | Hermes plugin enable.
- Problem: EVERY user gets ALL guards regardless of need.

## The operator's requirement
"Users should only get what they need. If they don't need codex or claude, they don't get it. Paladin is always installed (default)." Great UX from within Hermes AND from the terminal.

## Design questions
1. pip: extras (`custodian-kernel[codex-guard]` etc.) vs one wheel with always-present scripts that self-explain when the integration is absent? Entry points can't be conditional in one wheel — how should the CLI surface behave for unneeded guards?
2. Managed installer (install-custodian.py): what flags/interactive UX? Defaults?
3. Hermes-native UX: what should the user type inside Hermes to get exactly the hermes-guard (not codex/claude)? Does the existing `hermes plugins enable` flow suffice, or is there a better pattern?
4. What does "uninstall what you don't need" look like (removing one guard's surface without breaking the kernel)?
5. Any pitfalls with the extras pattern for this kind of security tooling (dependency resolution, entry-point discovery, plugin enablement)?

## Return
Concrete recommended UX (exact commands a user types for: minimal install, kernel+paladin only; +codex; +claude; +hermes-from-Hermes), the pitfalls to avoid, and a verdict: which single UX pattern is best-in-class for this tool.
